01

The website

A calm, mobile-first site where a woman dealing with anxiety or anger can feel understood, trust Sarah, and book a session in under two minutes.

Pages

AddressWhat it does
/Home. "Find your calm again", words that light up as you scroll, the meaning of ठहराव, a breathing circle, three steps, Sarah, and a closing call to book.
/aboutSarah's photo, short bio, CBT in plain words, qualifications, languages.
/servicesAnxiety and anger support, fees, the free first session, the cancellation policy.
/bookPick "First session" or "Individual session", and the Cal ID calendar opens inline.
/faqEight short answers, including emergencies and the forms sent after booking.
/contactEmail, WhatsApp button, and a three-field form (Formspree).
/privacy, /termsPlain-language drafts written for India's DPDP Act. Have them reviewed before launch.
/404A gentle "page not found".

Also generated automatically: sitemap-index.xml, robots.txt, canonical links, Open Graph tags (for WhatsApp link previews) and the favicon.

The calm motion

  • The wheel. Soft ripple rings, from the logo mark, sit behind every page. They breathe slowly and turn as you scroll.
  • Drift-in. Text and cards fade up gently, with a slight blur clearing, as they enter the screen.
  • Words that light up one by one while a section stays pinned (on Home and About).
  • Lines that draw between steps as you scroll, and a breathing circle (5 seconds in, 5 seconds out).

All of this is CSS plus about 1 KB of plain JavaScript. Anyone with "reduce motion" switched on sees a still page, and all content shows even with JavaScript off.

How the pieces fit

The site is only static files. Railway builds them from GitHub and serves them with Caddy, a tiny web server. Bookings live in Cal ID, payments in Razorpay, and messages go through Formspree to Sarah's email. No client data is stored on the website itself.

Folder structure

  config/site.ts        ← every value you'll edit (email, fees, links…)
  components/           Header, Footer, Logo, BookingEmbed, Wheel, …

Dockerfile, Caddyfile   how Railway builds and serves it

Code on GitHub

The repo mirkarusama/Thehraav is empty for now. Pick one of these two ways to fill it.

Easiest

Let Claude push it

  1. Install the Claude GitHub App on the repo: github.com/apps/claude. Choose "Only select repositories" and pick Thehraav.
  2. Tell Claude in the project thread that it's done. The code goes to main.
Do it yourself

Push the zip

Download thehraav-site.zip from the project files. It includes the full git history. Then run:

unzip thehraav-site.zip
cd thehraav
git remote set-url origin https://github.com/mirkarusama/Thehraav.git
git push -u origin main
05

Run it locally

You need Node 22.23 or newer.

npm install
npm run dev        # http://localhost:4321 with live reload
npm run build      # builds the static site into dist/
npm run preview    # serves the built site

Optional, if you have Docker and want to test exactly what Railway runs:

docker build -t thehraav .
docker run --rm -p 8080:8080 thehraav    # http://localhost:8080

Editing content

Almost everything you'll change lives in one file, src/config/site.ts. Change a value, push, and Railway redeploys.

To changeEdit
Email, WhatsApp, socialssite.contact, site.social. WhatsApp is digits only, with country code, e.g. 919876543210
Fee, lengths, hourssite.sessions
Booking links, switch booking onsite.booking (set live: true once Cal ID is ready)
Contact formsite.formspreeId
Footer links and textfooter in the same file
Site addresssite.url, or a SITE_URL variable on Railway
Legal detailssite.legalDetails, legalUpdated, legalDraft
Page wordingsrc/pages/*.astro (plain HTML)
Cancellation wordingsrc/components/CancellationPolicy.astro (used on 4 pages)
Colours and fontsTop of src/styles/global.css

Any value still in [SQUARE BRACKETS] shows on the page with a yellow highlight, so it's easy to spot. Social links stay hidden until they're filled in.

Swapping the logo and photo

  • Logo: replace public/assets/logo.svg with the final file, keeping the same name. It sits in a fixed-size box, so nothing shifts. For a PNG, add it to public/assets/ and change logo.src in site.ts. Then replace favicon.svg, favicon-32.png, apple-touch-icon.png and og-image.png (1200×630) with versions of the new mark.
  • Photo: save Sarah's photo as WebP, about 640×800 (portrait, 4:5), at public/images/sarah-placeholder.webp, or change psychologist.photo. It's cropped into an arch shape automatically.
07

Deploy on Railway

Railway finds the Dockerfile and does everything else. Node builds the site, then Caddy serves it using about 15–20 MB of RAM, with no Node process running.

  1. Sign in at railway.com with GitHub, and choose the Hobby plan.
  2. Click New Project → Deploy from GitHub repo. The first time, allow Railway's GitHub app to see Thehraav.
  3. Pick mirkarusama/Thehraav. Railway detects the Dockerfile and starts building. Leave the start command and port empty, because Caddy listens on Railway's $PORT automatically.
  4. Wait for the deploy to turn green (the first build takes about 1–2 minutes).
  5. Open the service, go to Settings → Networking → Generate Domain, and choose the name thehraav if it's free. You get https://thehraav.up.railway.app with HTTPS already on.
  6. If the address is different, go to Variables → New Variable and add SITE_URL = your address (e.g. https://thehraav-production.up.railway.app), then redeploy. This keeps canonical links, the sitemap and WhatsApp previews correct.
  7. Open the site and click through every page. From now on, every push to main redeploys automatically.

Keeping usage low on Hobby. It's one small service with no database and no volumes. Optionally, under Settings → Deploy you can set a memory limit around 128 MB. Railway's Serverless setting (app sleeping) cuts usage further, but the first visit after a quiet spell is a second or two slower. For a site people find when they're struggling, leaving it off is kinder.

08

Contact form (Formspree)

The form's button stays disabled until a form ID is added, so nothing can be lost by accident.

  1. Sign up at formspree.io with thehraavcounselling@outlook.com and verify the email.
  2. Create a new form called "Thehraav website". Copy the ID from its endpoint: https://formspree.io/f/xyzabcd.
  3. Put it in site.ts: formspreeId: 'xyzabcd'. Push the change.
  4. In Formspree form settings, add the live domain under allowed domains (this stops spam from other sites).
  5. Send a test message from the live site. Check that it arrives, including in spam.

The form sends name, email and message only. It has a hidden spam trap and works even if JavaScript fails.

09

Bookings (Cal ID + Razorpay)

All of this happens in Sarah's Cal ID account. The website only shows the calendar. Until you switch it on, the Book page shows a friendly "coming soon" note that points to Contact.

Labels may differ. Cal ID is a fork of Cal.com. Menu names below follow Cal.com and Cal ID's help pages, so if a label is slightly different, look for the closest match.

A. Account, calendar and video

  1. Sign up at cal.id with Sarah's Google account. Choose the username thehraav.
  2. Settings → Calendars: connect Google Calendar, and turn on check for conflicts so busy times are hidden. Make it the calendar that new bookings are added to.
  3. Availability: Monday to Friday, 10:00–19:00, time zone Asia/Kolkata. Don't add breaks or daily limits.
  4. Apps → Google Meet → Install. Each booking then gets its own Meet link.

B. Razorpay

  1. Activate Sarah's Razorpay account (KYC) at razorpay.com.
  2. In Cal ID: App store → search "Razorpay" → Install, log in to Razorpay and authorise Cal ID (Cal ID's guide).

C. Two event types

First session (free)

  • Title: Free first session
  • Slug: free-first-session
  • Duration: 20 minutes
  • Location: Google Meet
  • No Razorpay
  • Description: "A relaxed first conversation for new clients. Talk, ask questions, and see if we're a good fit."

Individual session (paid)

  • Title: Individual session
  • Slug: individual-session
  • Duration: 50 minutes
  • Location: Google Meet
  • Apps tab → Razorpay: ₹1,200, INR
  • Description: include the cancellation policy (below)

Cancellation policy text (paste into both event descriptions):

Please give at least 24 hours' notice to cancel or reschedule, using the link in your confirmation email. Late cancellations or missed sessions may be charged at half the session fee.

For both events, open Limits and set minimum booking notice to 24 hours. If Cal ID offers a minimum notice for cancelling or rescheduling, set that to 24 hours too. If not, the policy is shown everywhere and Sarah handles late cancellations by hand. Cal ID can't check whether someone is a "new client", so Sarah can cancel repeat free bookings.

D. Three gentle booking questions

In each event: Advanced → Booking questions → Add a question. Name and email are already there.

QuestionTypeRequired
What would you like some help with? (A few words is fine)Long textNo
Which language would you prefer?Radio: English · Hindi · Either is fineNo
Have you had counselling or therapy before?Radio: Yes · No · Prefer not to sayNo

E. Confirmation email with forms, and reminders

  1. Sarah makes two Google Forms in her account: Consent form and Intake form. Copy both share links.
  2. Workflows → New, trigger When new event is booked, action Send email to attendee, for both events: 
    Hi {ATTENDEE_NAME}, thank you for booking.

Before our first session, please fill in these two short forms:
Consent form: [link]
Intake form: [link]

Your video link is in your confirmation email.
Warmly, Sarah
  3. A second workflow: trigger Before event starts, 24 hours, Send email to attendee as a reminder. You can add another for 1 hour before.
  4. If Workflows isn't available on her plan, paste the two form links into each event's description instead. They then appear in the confirmation email.

F. Switch booking on in the website

// src/config/site.ts
booking: {
  base: 'https://cal.id',
  live: true,                                   // ← turn on
  freeEvent: 'thehraav/free-first-session',
  regularEvent: 'thehraav/individual-session',
},

Push, wait for the redeploy, then open /book and click each card. The Cal ID calendar should load inside the page. Every "Book" button on the site leads here, and /book#free or /book#regular opens that event directly.

If the calendar stays blank (Cal ID may block plain embedding): in Cal ID open Event → Embed → Inline → Get Code, copy the snippet, and send it to Claude in the project thread. The BookingEmbed component switches to Cal ID's official embed script (cal.id/embed-link/embed.js), which is a small change. Visitors always see an "open in a new tab" link as a backup, so bookings still work in the meantime.

Fallback plan: if Cal ID doesn't work out, use Cal.com (free) for scheduling, plus a Razorpay Payment Page link in the paid event's confirmation. The trade-off is that payment isn't enforced at booking, so Sarah checks it by hand.

10

Custom domain, later

  1. Buy the domain (e.g. thehraav.com) from any registrar.
  2. Railway: Settings → Networking → Custom Domain, add thehraav.com and www.thehraav.com. Railway shows a DNS record for each.
  3. At the registrar, add those records: a CNAME for www, and an ALIAS / ANAME / flattened CNAME for the root (Cloudflare DNS handles this well). Wait for Railway to show it as verified. HTTPS is automatic.
  4. Railway Variables: set SITE_URL=https://thehraav.com, then redeploy.
  5. Redirect one form to the other (usually www → root) at the registrar or DNS provider.
  6. When hello@thehraav.com is ready, change contact.email in site.ts. Also update it in Cal ID, Formspree and Google Business Profile.
  7. Update the website link in Google Business Profile, Search Console, Cal ID and social profiles.

If something breaks

What you seeWhat to do
Railway build fails at npm ciMake sure package-lock.json is committed, then redeploy.
"Application failed to respond"Check that no custom port or start command is set on the service. Caddy uses $PORT by itself.
Link previews show the wrong addressSet SITE_URL on Railway and redeploy.
Book page says "coming soon"booking.live is still false.
Calendar area is blankSee the note at the end of stage 09F.
Form button is greyed outformspreeId is still a placeholder.
Form says "something went wrong"The live domain is missing from Formspree's allowed domains, or the form ID is wrong.
